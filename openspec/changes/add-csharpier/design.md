## Context

The repo already uses a local .NET tool manifest (`.config/dotnet-tools.json`) for `dotnet-stryker` 4.16.0. CSharpier 1.3.0 is a dotnet tool targeting net8.0+ that supports C# 14 / .NET 10, so it runs under the existing .NET 10 SDK. The CI workflow (`.github/workflows/dotnet.yml`) has two jobs today: `build` (restore → build → test, on push and PR) and `mutation-core` (Stryker, PR only). The two jobs run independently, so Stryker currently runs even when the build is broken. No formatter is present; the previous `add-dotnet-editorconfig` change deliberately deferred CI style enforcement.

## Goals / Non-Goals

**Goals:**

- Pin CSharpier as a local tool so every developer and CI uses the same version.
- Make formatting non-negotiable: an unformatted change fails CI *before* any restore/build/test work, and never triggers the slow Stryker job.
- Make the one-time reformat a clean, blame-ignorable commit.

**Non-Goals:**

- No `.csharpierrc` config — CSharpier defaults are the point; adding config re-introduces the bikeshedding this change removes.
- No local pre-commit hook or editor-plugin configuration in the repo (CI is the enforcement boundary; editor plugins are a per-developer convenience outside this change).
- No `CSharpier.MsBuild` package (build-coupled formatting), which would rewrite files on the Debug builds CI uses.

## Decisions

### Decision: Local dotnet tool, not global install or MsBuild package

`dotnet tool install csharpier` appends to the existing `.config/dotnet-tools.json`, matching how `dotnet-stryker` is managed. CI already runs `dotnet tool restore` in the mutation job, so the mechanism is established.

- Alternative (rejected): `CSharpier.MsBuild` NuGet package. In Debug it *formats* on build (rewriting files during CI's Debug build), and it requires a package reference in each project. Heavier and misaligned with the Debug-based CI.
- Alternative (rejected): global install. Not reproducible across machines/CI.

### Decision: Fail-early check in the `build` job, gated `mutation-core`

`dotnet csharpier check .` runs as the first step after tool restore in the `build` job, before `dotnet restore`/`build`/`test`. It exits non-zero on any unformatted file, failing fast with minimal machine time. `mutation-core` gains `needs: build`, so GitHub Actions skips Stryker whenever the build job (including the format check) fails.

- Alternative (rejected): a separate `format` job. Adds a second status and job for marginal benefit in a small repo; a single unified build status is simpler, and fail-early ordering already prevents wasted build/test time.

### Decision: No `.csharpierrc`, ship defaults

Defaults (`printWidth: 100`, spaces, LF) remove all configuration surface. The `// <auto-generated />` header on EF `*.Designer.cs` and `NaggerDbContextModelSnapshot.cs` means CSharpier skips them by default (`--include-generated` off), so generated code does not churn.

### Decision: `.git-blame-ignore-revs` for the reformat commit

The mechanical reformat touches nearly every `.cs` file. Recording its commit hash in `.git-blame-ignore-revs` (a filename GitHub honors automatically) keeps `git blame` pointing at the last semantic change.

## Risks / Trade-offs

- [The reformat produces a large, noisy diff touching every hand-written `.cs` file] → Land it as a single dedicated commit, separate from the tooling/CI commit, and list it in `.git-blame-ignore-revs`.
- [Format check requires `dotnet tool restore` in the `build` job, which it currently lacks] → Add the `Restore tools` step immediately before the check; the manifest is committed, so restore is deterministic and fast.
- [A developer without an editor plugin will hit a red build on unformatted code] → Acceptable: CI is the enforcement boundary, and the failure message points to `dotnet csharpier format .` to fix locally.
- [Generated-code assumptions may be incomplete] → Verify after the reformat that no `*.Designer.cs`/snapshot files were modified; if CSharpier touches them, add them to a `.csharpierignore` (a follow-up decision, not anticipated).
